# GOAL

## Что строим

Agents Flow — система, где задача ставится голосом или текстом, агент готовит план,
получает подтверждение, реализует задачу и публикует результат только после приёмки.

Два компонента:

| Компонент | Папка | Роль |
|---|---|---|
| Сервер | `server/` | Панель, API, PostgreSQL, Telegram, транскрибация, MCP |
| Harness | `harness/` | Один бинарник в Git-проекте: получает задачу, запускает Deep Agents |

## Для кого

Для владельца системы — одного человека, который ставит задачи, а не пишет их.
Панель нужна, чтобы видеть ход работы и принимать решения. Telegram — чтобы
работать без открытого ноутбука.

## Главная идея

Harness не знает, чем занимается проект. Всё знание о конкретной работе живёт
в skills — Markdown-инструкциях, которые назначаются агенту в панели.

```
Harness  = универсальный исполнитель
Skills   = вся предметная логика
Сервер   = состояние, решения, история
```

Один и тот же бинарник обслуживает лендинг, Python-сервис, ресёрч или SEO-текст —
разница только в наборе skills.

## Критерии успеха

1. Задача от голосового сообщения до готовой работы проходит без ручных
   команд в терминале.
2. Ни одно изменение кода не происходит до подтверждения плана.
3. Ни один push и ни один деплой не происходит до подтверждения публикации.
4. Новая предметная область подключается добавлением skills, а не правкой кода
   сервера или Harness.
5. История задачи не теряется при ошибке, обрыве связи или истечении аренды.
6. Секреты не попадают в Git, логи, skills, YAML и отчёты.
7. Все файлы кода укладываются в 150 строк; логика делится на модули.

## Чего не делаем

- Свою систему оркестрации, очереди, WebSocket, LangGraph.
- Универсальную платформу автоматизации для чужих команд.
- Биллинг, роли, дашборды, чат с агентом.
- Хранение секретов в skills.
