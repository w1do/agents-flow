## ADDED Requirements

### Requirement: Вход оператора по токену

Панель SHALL принимать `HARNESS_ADMIN_TOKEN`, введённый оператором на экране «Вход», и держать его только в памяти
вкладки. Панель MUST передавать токен заголовком `Authorization: Bearer` в каждом запросе. Токен MUST NOT сохраняться в
`localStorage`, `sessionStorage`, cookie и URL. Сервер MUST отвечать 401 без подробностей при отсутствующем, неверном
или не настроенном токене. Серверные сессии и вход по паролю на этом этапе не вводятся (design.md, «Исключение этапа»).

#### Scenario: Верный токен

- **WHEN** оператор вводит верный токен и открывает канбан
- **THEN** данные загружены, каждый запрос содержит заголовок `Authorization: Bearer`

#### Scenario: Неверный токен

- **WHEN** оператор вводит токен, который сервер не принимает
- **THEN** ответ 401, экран «Вход» показывает общее сообщение без значения токена

#### Scenario: Перезагрузка вкладки

- **WHEN** оператор перезагружает вкладку
- **THEN** токен забыт, экран «Вход» просит ввести его заново

### Requirement: Настройки проектов

Панель SHALL показывать список проектов, создавать проект, изменять его поля и отключать его через
`/api/console/projects`, которые вызывают функции `services/projects`. Список MUST включать отключённые проекты.
Панель MUST NOT показывать и принимать значение ключа репозитория: поле `access_ref` содержит только ссылку vault.

#### Scenario: Список проектов

- **WHEN** оператор открывает экран «Проекты»
- **THEN** видны все проекты, у отключённого проекта статус `disabled`

#### Scenario: Создание проекта

- **WHEN** оператор отправляет форму с новым `id` и корректными полями
- **THEN** проект создан со статусом `active`, экран показывает его в списке

#### Scenario: Занятый id

- **WHEN** оператор создаёт проект с `id`, который уже есть
- **THEN** ответ 409 `project_conflict`, экран показывает ошибку по коду, существующий проект не меняется

#### Scenario: Редактирование проекта

- **WHEN** оператор меняет поля существующего проекта
- **THEN** в запросе только изменённые поля, блок `repo` передан целиком вместе с `access_ref`, `id` не меняется

#### Scenario: Ошибка проверки полей

- **WHEN** сервер отвечает 422 `invalid_project` со списком `fields`
- **THEN** подсвечены только поля из списка, значения полей в сообщениях не выводятся

#### Scenario: Отключение проекта

- **WHEN** оператор подтверждает отключение проекта
- **THEN** статус проекта становится `disabled`; задачи в работе по проекту не останавливаются

### Requirement: Канбан и карточка задачи

Панель SHALL показывать задачи по статусам ТЗ v5 с фильтром по проекту и карточку задачи с лентой событий,
веткой, MR, итогом и решением маршрутизации.

#### Scenario: Канбан

- **WHEN** администратор открывает канбан
- **THEN** задачи сгруппированы по статусам, задачи `trash` скрыты по умолчанию

#### Scenario: Карточка задачи

- **WHEN** администратор открывает задачу
- **THEN** видны события в порядке времени, ветка, ссылка на MR и итог

### Requirement: Создание задачи из панели

Панель SHALL создавать задачу из текста и выбранного проекта через тот же сервис, что Telegram. Задача MUST
сразу переходить в `planning` с источником `console`, без маршрутизации через Polza.

#### Scenario: Новая задача

- **WHEN** администратор отправляет текст и проект
- **THEN** создана задача `plan` в статусе `planning` с источником `console` и событием в ленте

#### Scenario: Неизвестный проект

- **WHEN** проект не указан в `harness.yaml`
- **THEN** ответ 422, задача не создана

### Requirement: Песочница и вывод агента

Панель SHALL показывать состояние песочницы и закреплённую задачу, ставить песочницу на паузу и возобновлять её
теми же функциями, что CLI, и показывать хвост вывода агента. Вывод MUST проходить redaction до отправки в браузер.

#### Scenario: Пауза занятой песочницы из панели

- **WHEN** администратор нажимает паузу во время активной задачи
- **THEN** ответ 409 с указанием задачи, песочница не ставится на паузу

#### Scenario: Секрет в логе агента

- **WHEN** `stderr.log` агента содержит значение OAuth-токена
- **THEN** в ответе вместо значения `[REDACTED]`

#### Scenario: Лог чужой задачи

- **WHEN** запрошен лог задачи, не закреплённой за песочницей
- **THEN** ответ 404, песочница не читается
