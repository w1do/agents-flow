## ADDED Requirements

### Requirement: Единственный клиент агента — OpenCode

Система SHALL запускать агента задач только клиентом OpenCode. Поле `workspaces[].agent`
MUST принимать только значение `opencode` (оно же — по умолчанию); конфигурация с иными
типами агента (`claude-code`, `codex` и другие) MUST отклоняться при загрузке настроек.

#### Scenario: Workspace со старым агентом

- **WHEN** в `harness.yaml` у workspace указан `agent: claude-code` или `agent: codex`
- **THEN** конфигурация отклоняется с понятной ошибкой, задача не запускается

#### Scenario: Значение по умолчанию

- **WHEN** поле `agent` у workspace не задано
- **THEN** используется `opencode`

### Requirement: Установка OpenCode закреплённой версией

Bootstrap песочницы SHALL устанавливать OpenCode закреплённой в настройках версией в формате
X.Y.Z и MUST NOT устанавливать Claude Code или Codex. Повторный запуск bootstrap с той же
версией MUST NOT переустанавливать пакет (идемпотентность). Некорректная версия или
неизвестный флаг версии Claude MUST завершать скрипт ошибкой аргументов до побочных эффектов.

#### Scenario: Повторный bootstrap

- **WHEN** bootstrap запускается второй раз на подготовленной песочнице с той же версией
- **THEN** скрипт завершается кодом 0, пакет OpenCode не переустанавливается

#### Scenario: Некорректная версия

- **WHEN** версия OpenCode передана не в формате X.Y.Z
- **THEN** bootstrap завершается кодом 2 до установок и изменений файловой системы

#### Scenario: Удалённый флаг Claude

- **WHEN** bootstrap вызывается с флагом `--claude-version`
- **THEN** скрипт завершается кодом 2 с сообщением о неизвестном аргументе

### Requirement: Инвентаризация пользовательской конфигурации

Реализация изменения MUST начинаться с инвентаризации пользовательской конфигурации OpenCode
владельца (`~/.config/opencode`): перечень файлов, ключей и мест подстановки секретов. В
репозиторий, спецификации, логи и память (Memory/RAG) MUST попадать только имена файлов,
ключей и плейсхолдеры; значения секретов — никогда. Имена переменных, ключей, команд и
целевых путей MUST определяться инвентаризацией и решением D-NN, а не предположениями.

#### Scenario: Секрет в перечне инвентаризации

- **WHEN** инвентаризация находит в конфигурации значение секрета (токен, ключ)
- **THEN** в репозиторий и отчёт попадает только плейсхолдер `{env:NAME}` с именем переменной, значение не переносится

#### Scenario: Неподтверждённый ключ конфигурации

- **WHEN** ключ или путь конфигурации OpenCode не подтверждён инвентаризацией или решением D-NN
- **THEN** он не добавляется в каталог-источник и в bootstrap

#### Scenario: Неизвестное на момент спецификации

- **WHEN** спека или код ссылаются на имя пакета, ENV, команду или путь конфигурации OpenCode
- **THEN** это имя пришло из инвентаризации (1.1) и закреплено в D-NN; содержимое `~/.config/opencode` на момент спецификации неизвестно

### Requirement: Конфигурация OpenCode из каталога-источника

Пользовательская конфигурация OpenCode SHALL разворачиваться в песочнице из
каталога-источника в репозитории, заполняемого по итогам инвентаризации. Bootstrap MUST
копировать файлы источника в целевые пути конфигурации OpenCode (закреплённые D-NN) без
изменения содержимого; права на каталоги конфигурации MUST ограничивать доступ остальных
пользователей. Прямое копирование живого `~/.config/opencode` в песочницу MUST NOT
выполняться.

#### Scenario: Развёртывание при bootstrap

- **WHEN** выполняется фаза setup bootstrap
- **THEN** файлы каталога-источника записаны в конфигурацию OpenCode песочницы, повторный запуск не портит их

#### Scenario: Обновление источника

- **WHEN** файлы источника в репозитории изменились и песочница подготовлена заново
- **THEN** в песочнице оказывается актуальная версия файлов конфигурации

### Requirement: Секреты только плейсхолдерами

Каталог-источник и развёрнутая конфигурация OpenCode MUST NOT содержать значений секретов:
допускаются только плейсхолдеры вида `{env:NAME}` и ссылки на переменные окружения. Значения
передаются только в env exec-команд и MUST проходить redaction до записи в лог, БД и
Telegram. Отсутствие секретных значений в источнике MUST проверяться тестом репозитория.

#### Scenario: Токен в файле источника

- **WHEN** в файл каталога-источника попало значение токена или ключа
- **THEN** тест репозитория падает, значение не попадает в git

#### Scenario: Значение в выводе bootstrap

- **WHEN** вывод bootstrap содержит значение секретной переменной окружения
- **THEN** в лог и БД уходит текст с `[REDACTED]` вместо значения
