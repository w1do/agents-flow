## ADDED Requirements

### Requirement: Задача реализации от очереди до MR

Задача `implement` SHALL браться из `backlog` по приоритету, выполняться исполнителем в ветке `task/<task_id>` и
после гейтов получать MR в основную ветку workspace. Сообщение в Telegram MUST получить строку «начата» при старте
агента и «готова, MR создан» со ссылкой на MR при успехе.

#### Scenario: Успешная задача

- **WHEN** исполнитель закоммитил изменения, тесты прошли
- **THEN** ветка запушена, создан MR, задача в `ready` со ссылкой на MR, в сообщении две строки этапов

### Requirement: Тесты не зелёные по умолчанию

Если у workspace не задана команда тестов, результат тестов SHALL быть «без тестов» и MUST NOT отображаться как
пройденный. Пройденными тесты считаются только по нулевому коду возврата заданной команды.

#### Scenario: Нет команды тестов

- **WHEN** у workspace нет `test_command`
- **THEN** задача получает отметку «без тестов», в сообщении нет слов «тесты пройдены»

#### Scenario: Тесты упали

- **WHEN** команда тестов вернула ненулевой код
- **THEN** задача в `error`, причина содержит хвост вывода без секретов, MR не создаётся

### Requirement: Секреты не уходят в репозиторий

Перед push система SHALL проверить diff ветки на шаблоны секретов и точные значения выданных на задачу кредов и
при находке MUST остановить доставку с причиной без значения секрета.

#### Scenario: Ключ в коде

- **WHEN** исполнитель добавил в код строку с API-ключом
- **THEN** push не выполняется, задача в `error`, в причине указан файл, но не значение

### Requirement: Идемпотентные гейты

Каждый гейт SHALL проверять, выполнен ли он уже. Повторный запуск после обрыва MUST продолжаться с первого
невыполненного шага и MUST NOT создавать второй MR для той же ветки.

#### Scenario: Обрыв после push

- **WHEN** worker перезапустился после успешного push, но до создания MR
- **THEN** push пропускается, создаётся один MR

#### Scenario: MR уже существует

- **WHEN** открытый MR из ветки `task/<id>` уже есть
- **THEN** новый MR не создаётся, задача ссылается на существующий

### Requirement: Нет изменений — нет готовности

Если исполнитель завершился без изменений относительно базы, задача SHALL перейти в `error` с причиной «нет изменений».

#### Scenario: Пустой результат

- **WHEN** агент завершился с кодом 0, но diff пуст
- **THEN** задача в `error` «нет изменений», MR не создаётся
