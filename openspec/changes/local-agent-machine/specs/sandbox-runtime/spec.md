## MODIFIED Requirements

### Requirement: Активация песочницы под задачу

Перед запуском агента система SHALL подключиться к машине, закрепить её за задачей, обновить репозиторий и создать
worktree на ветке `task/<task_id>` от указанной базы. Закрепление песочницы и выбор задачи MUST выполняться одной
транзакцией. Повторная активация той же задачи MUST возвращать текущее состояние без повторной подготовки.
Песочница MUST NOT закрепляться за двумя задачами одновременно. Песочница в статусе `error` MUST NOT брать задачи.
Активация MUST NOT продлевать время жизни машины и MUST NOT устанавливать инструменты.

#### Scenario: Песочница занята

- **WHEN** песочница выполняет задачу A, а в очереди задача B
- **THEN** задача B остаётся в очереди в прежнем статусе, пока песочница не освободится

#### Scenario: Повторная активация

- **WHEN** worker перезапустился и снова активирует ту же задачу
- **THEN** worktree и ветка не пересоздаются, агент не запускается второй раз

#### Scenario: Песочница в ошибке

- **WHEN** песочница в статусе `error`, а в очереди есть задача
- **THEN** задача остаётся в очереди, песочница не используется

### Requirement: Креды не остаются в песочнице

Секреты SHALL передаваться на машину агента только в окружении конкретной команды и MUST NOT записываться в файлы
машины. Это касается и ключей из vault: они передаются в env `agent init`, активации и запуска агента.
Файлы `agent init` и запуска агента MUST NOT содержать секретов. Текст, прочитанный с машины, MUST проходить
redaction, в том числе по значениям из vault, до записи в лог, БД или Telegram.

#### Scenario: Проверка диска

- **WHEN** после запуска агента на машине ищут значение выданного токена в `~` и в каталоге репозитория
- **THEN** значение не найдено

#### Scenario: Секрет в выводе агента

- **WHEN** `stderr.log` агента содержит значение OAuth-токена
- **THEN** в лог и БД уходит текст с `[REDACTED]` вместо значения

#### Scenario: Токен задачи после рестарта worker

- **WHEN** `stderr.log` агента содержит токен задачи, а worker, выдавший токен, перезапущен
- **THEN** токен заменяется на `[REDACTED]` по шаблону формата токена задачи

#### Scenario: Ключ из vault в выводе

- **WHEN** вывод `agent init`, активации или агента содержит значение ключа из vault
- **THEN** в лог и БД уходит текст с `[REDACTED]` вместо значения

### Requirement: Пауза только после очистки

После завершения задачи система SHALL удалить worktree, локальную ветку и каталог файлов задачи, отозвать токены задачи и только при
успехе очистки освободить песочницу (статус `paused`, `current_task_id` пуст). При ошибке очистки песочница MUST
переходить в `error` и MUST NOT освобождаться. Освобождение MUST NOT вызывать никаких действий над самой машиной.

#### Scenario: Очистка не удалась

- **WHEN** удаление worktree вернуло ненулевой код
- **THEN** песочница в статусе `error`, не освобождена, причина записана

#### Scenario: Успешная очистка

- **WHEN** задача завершилась и очистка прошла
- **THEN** токены задачи отозваны, песочница в статусе `paused`, `current_task_id` пуст

### Requirement: Ручная пауза и возобновление

Оператор SHALL иметь одну команду для паузы и одну для возобновления песочницы из конфигурации, а также команду
статуса. Пауза и возобновление MUST менять только статус строки песочницы и MUST NOT обращаться к машине, кроме
проверки доступности при возобновлении. Пауза MUST отказывать, если за песочницей закреплена активная задача.
Команды подготовки (bootstrap) MUST NOT существовать: подготовка проекта — `agent init`.

#### Scenario: Пауза занятой песочницы

- **WHEN** оператор вызывает паузу во время активной задачи
- **THEN** команда отказывает с указанием задачи

#### Scenario: Возобновление песочницы в ошибке

- **WHEN** оператор вызывает возобновление песочницы в статусе `error` без закреплённой задачи
- **THEN** машина проверяется командой `true`, статус становится `paused`, колонки запуска агента сбрасываются

#### Scenario: Возобновление свободной песочницы

- **WHEN** оператор вызывает возобновление песочницы в статусе `paused`
- **THEN** статус не меняется, на машине ничего не выполняется

#### Scenario: Повторный bootstrap

- **WHEN** оператор повторно выполняет подготовку проекта командой `agent init` (сценарий сохраняет прежнее имя)
- **THEN** команда завершается с кодом 0, репозиторий не клонируется заново, инструменты не устанавливаются

#### Scenario: Старая команда bootstrap

- **WHEN** оператор вызывает `harness-server sandbox bootstrap`
- **THEN** команда не найдена (код выхода 2), подсказка в справке: проект подключается `agent init <project>`

## ADDED Requirements

### Requirement: Маркер готовности проекта перед задачей

Перед активацией песочницы worker SHALL проверить маркер `~/.harness/projects/<workspace_id>.ready` на машине.
Если маркера нет, задача MUST перейти в `error` с причиной `project_not_initialized: выполните agent init
<workspace_id>`, а fetch и worktree MUST NOT выполняться. Маркер MUST ставиться только командой `agent init` по
успешному завершению всех её шагов.

#### Scenario: Проект не подключён

- **WHEN** в очереди задача workspace `demo`, а `agent init demo` не выполнялся
- **THEN** задача в `error` с причиной `project_not_initialized: выполните agent init demo`, песочница освобождена, fetch не выполнялся

#### Scenario: Проект подключён

- **WHEN** маркер `demo.ready` есть
- **THEN** активация идёт как обычно: fetch по адресу из конфига, worktree на `task/<id>`

#### Scenario: Сбой agent init

- **WHEN** `agent init demo` завершился ошибкой на шаге клона
- **THEN** маркер `demo.ready` не поставлен (или снят, если был от предыдущего успешного запуска), задачи workspace получают `project_not_initialized`
