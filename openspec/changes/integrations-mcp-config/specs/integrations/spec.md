## ADDED Requirements

### Requirement: Раздел MCP-серверов без секретов

Платформа SHALL хранить MCP-серверы агента в Postgres: имя, описание, транспорт, адрес или команду, `env` и `headers`.
Значение `env` или `headers` MUST быть обычным текстом или ссылкой `vault:<project>/<service>/<name>`; значения секретов
MUST NOT храниться в БД. Литеральное значение в заголовке авторизации или в секретной переменной MUST отклоняться.

#### Scenario: Чтение раздела

- **WHEN** оператор выполняет `harness-server mcp show vault`
- **THEN** в выводе ссылка `vault:…`, значения ключа нет

#### Scenario: Литеральный ключ

- **WHEN** оператор добавляет сервер с заголовком `Authorization: Bearer abc123`
- **THEN** команда отклоняется с указанием поля, запись не создаётся

### Requirement: Конфиг MCP для агента

При каждом запуске агента сервер SHALL генерировать MCP-конфиг из раздела MCP, встроенного `project-memory` (если память
включена) и `agents-flow`. Ссылки на vault MUST разворачиваться сервером и передаваться агенту только через окружение;
конфиг MUST содержать только плейсхолдеры.

#### Scenario: Запуск с сервером из vault

- **WHEN** в разделе есть сервер с заголовком `Bearer vault:…`
- **THEN** в env агента есть значение ключа, в файлах песочницы его нет, сервер подключён

#### Scenario: Изменение раздела

- **WHEN** оператор удалил сервер из раздела
- **THEN** следующий запуск агента идёт без этого сервера, bootstrap не нужен
