# Proposal: check-tasks

> Задачи проверки (класс «проверка»). Волна 1 (после MVP), см. PLAN.md.

## Why

«Проверь, работает ли» требует запустить код, но без коммитов и мерджа (ТЗ §5.0 класс 2).

## What Changes

- Класс `check` в маршрутизации, кнопка уточнения между `work` и `check`
- Задача `kind=check`: песочница, команда тестов/сборки workspace, только чтение
- Результат в Telegram, никаких push и MR

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `task-lifecycle`: добавляются требования (ADDED): Проверка без изменений, Сомнение между работой и проверкой.

## Impact

- Зависит от: `mvp-09-delivery-mr`.
- Ссылки: ТЗ §5.0 класс 2.
- Затрагивает ARCHITECTURE.md (разделы по теме) и, при новых инструментах, docs/mcp-agents-flow.md.

## Не входит

- Исправление по итогам проверки (это новая задача `work`)
