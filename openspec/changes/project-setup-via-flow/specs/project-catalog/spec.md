# Spec Delta

## Purpose

Проекты (workspace), с которыми работает харнесс, хранятся на сервере и заводятся оператором в консоли
или через API. Машина агента получает настройки проекта по его идентификатору и создаёт свою локальную
папку, без ручной правки файлов.

## ADDED Requirements

### Requirement: Создание проекта на сервере

Сервер SHALL создавать проект по идентификатору `id` (уникальному, строка из латинских букв, цифр и дефисов),
названию, голосовым алиасам, блоку `repo`, `default_branch`, `test_command` (необязательный), `agent` и
`agent_max_turns`. Поля MUST проверяться до записи в базу; неверное значение отклоняется ответом с именем поля
без значения.

#### Scenario: Новый проект с корректными полями
- **WHEN** оператор создаёт проект с уникальным `id` и заполненными обязательными полями
- **THEN** сервер сохраняет проект и возвращает его с присвоенным статусом `active`

#### Scenario: Повтор идентификатора
- **WHEN** оператор создаёт проект с `id`, который уже занят
- **THEN** сервер отклоняет запрос ошибкой конфликта и не меняет существующий проект

#### Scenario: Ключ записи не ссылкой
- **WHEN** в поле `repo.access_ref` передано значение, не похожее на ссылку `vault:<project>/<service>/<name>`
- **THEN** сервер отклоняет запрос, а значение в ответе не показывает

### Requirement: Ключ репозитория только ссылкой

Проект SHALL хранить ключ записи репозитория только как ссылку `repo.access_ref` на vault. Значение ключа
MUST NOT храниться в базе, в API-ответах, в журнале и в консоли.

#### Scenario: Чтение проекта
- **WHEN** оператор запрашивает проект через API
- **THEN** ответ содержит ссылку `access_ref`, но не содержит значения ключа

### Requirement: Изменение и отключение проекта

Сервер SHALL позволять изменить поля проекта и отключить его. Отключённый проект MUST NOT принимать новые
задачи и MUST NOT выдаваться машине агента для новой инициализации. Уже созданные задачи проекта
сохраняются без изменений.

#### Scenario: Отключение проекта с задачами
- **WHEN** оператор отключает проект, по которому есть задачи в работе
- **THEN** задачи в работе доходят до своего статуса, новые задачи по проекту отклоняются

### Requirement: Выдача настроек проекта машине агента

Сервер SHALL отдавать настройки активного проекта по его `id` тому, кто предъявил операторский токен.
Ответ MUST содержать только поля, нужные для локального конфига проекта, и MUST NOT содержать значения ключей.

#### Scenario: Запрос настроек существующего проекта
- **WHEN** машина агента запрашивает настройки проекта `demo` с верным токеном
- **THEN** сервер возвращает поля проекта, включая ссылку `access_ref`

#### Scenario: Запрос без токена или неизвестного проекта
- **WHEN** запрос пришёл без токена или проект с таким `id` не найден
- **THEN** сервер отвечает ошибкой без подробностей о том, какое условие не выполнено
