# Proposal

## Why

Проект существует только как ТЗ и документация: в `server/`, `harness/` и `deploy/`
лежат README без кода. Нужен один вертикальный прототип, который целиком проходит
путь «голосовая задача → план → подтверждение → реализация → проверки → приёмка →
публикация», чтобы проверить саму идею до вложений в качество и надёжность.

## What Changes

- Новый сервер `server/`: FastAPI + PostgreSQL + SQLAlchemy + Alembic, JWT-логин
  администратора, одноразовые init-коды и agent-токены.
- Проекты, агенты, skills (категории, карточки, версии, хеши, назначение агенту,
  снимок на задачу) — через REST API.
- Жизненный цикл задачи: 12 статусов, атомарная аренда через
  `FOR UPDATE SKIP LOCKED`, heartbeat/TTL, решения по плану и результату,
  лента событий, идемпотентность по ключу.
- Telegram-приём: текст, voice, audio; транскрибация через один настраиваемый
  провайдер; кнопки решений и уведомления.
- MCP endpoint с 11 инструментами отчётности агента поверх общего service layer.
- Панель на 5 экранов: `/login`, `/projects`, `/projects/{id}`, `/tasks/{id}`,
  `/skills`.
- Новый Harness `harness/`: Go-бинарник `harness init <project_id>` и
  `harness run` — аренда, heartbeat, синхронизация skills, worktree `task/<id>`,
  запуск раннера агента по этапам.
- Развёртывание: `deploy/db/docker-compose.yml` (PostgreSQL) и корневой
  `docker-compose.yml` (`migrate`, `server`, `console`).
- Конфигурация: `.env.example` и заполненный локальный `.env` со всеми
  переменными; внешние токены (Telegram, транскрибация) подставляет
  пользователь после сдачи, сервер стартует и без них в режиме прототипа.
- Одна задача реализации, выполняемая суб-агентами: Sol пишет код, Terra
  запускает проверки, Astra ревьюит, documenter обновляет документы.

## Capabilities

### New Capabilities

- `server/auth`: вход администратора по JWT, одноразовые init-коды, agent-токены
  с ограниченным доступом.
- `server/projects`: проекты и агенты проекта, генерация init-кода, карточка
  агента со статусом и heartbeat.
- `server/skills`: категории, карточки skills, версии и хеши, назначение агенту,
  снимок skills на задачу.
- `server/tasks`: статусы и переходы, аренда и heartbeat, решения пользователя,
  события, идемпотентность.
- `server/telegram`: приём текста и голоса, транскрибация, кнопки решений,
  уведомления, защита webhook.
- `server/mcp`: 11 MCP-инструментов отчётности агента с проверкой lease и прав.
- `server/panel`: 5 экранов панели, показывающих ход задачи и skills.
- `harness/runtime`: init в Git-проекте, рабочий цикл `run`, worktree, синхронизация
  skills, запуск агента по этапам.
- `deployment`: compose-стеки, миграции до старта сервера, переменные окружения.

### Modified Capabilities

Нет: спецификаций у проекта ещё нет.

## Impact

- Код: `server/` (Python), `harness/` (Go), `deploy/`, корневой
  `docker-compose.yml`, `.env.example`, `.gitignore`.
- Контракты: REST `/api/v1`, MCP `/mcp`, формат `workflow/config.yaml` и skills —
  впервые появляются, обратной совместимости не требуется.
- Зависимости: Python 3.12, FastAPI, SQLAlchemy 2, Alembic, Pydantic 2, httpx,
  bcrypt/JWT, MCP Python SDK, OpenAI-совместимый API транскрибации; Go 1.23+,
  стандартная библиотека и `gopkg.in/yaml.v3`.
- Данные: одна Alembic-миграция создаёт полную схему из ТЗ.
- Внешние системы: Telegram Bot API, провайдер транскрибации, Git,
  Dokploy — подключаются только через переменные окружения и skills.
- Ограничение объёма: прототип, а не продакшн; роли, WebSocket, очереди,
  несколько агентов на проект не входят.
