# Spec Delta

## Purpose

Показывает одному администратору, что происходит с проектом и задачей,
и даёт принять решения без терминала и без чтения логов.

## ADDED Requirements

### Requirement: Экран входа
Система SHALL предоставлять экран `/login`, принимающий email и пароль
и запоминающий сессию панели.

#### Scenario: Вход
- **WHEN** администратор вводит верные учётные данные
- **THEN** он попадает в список проектов

#### Scenario: Неверные данные
- **WHEN** введён неверный пароль
- **THEN** остаётся экран входа с понятной ошибкой

### Requirement: Экран проектов
Система SHALL показывать на `/projects` список проектов с активными задачами
и агентами и SHALL позволять создать проект.

#### Scenario: Список
- **WHEN** администратор открыл `/projects`
- **THEN** видны проекты, их активные задачи и агенты

#### Scenario: Создание
- **WHEN** администратор создал проект из формы
- **THEN** проект появляется в списке без перезагрузки страницы вручную

### Requirement: Экран проекта
Система SHALL показывать на `/projects/{id}` задачи сгруппированные по статусам,
агентов проекта и кнопку подключения Harness с выдачей init-кода.

#### Scenario: Группировка задач
- **WHEN** в проекте есть задачи в трёх статусах
- **THEN** они показаны отдельными группами с количеством

#### Scenario: Подключение Harness
- **WHEN** администратор нажал «Подключить Harness»
- **THEN** на экране появился init-код и команда `harness init` для копирования

### Requirement: Экран задачи
Система SHALL показывать на `/tasks/{id}` план, решения, ленту событий,
результаты проверок, отчёт и итог публикации, и SHALL позволять принять решение.

#### Scenario: Полный ход работы
- **WHEN** администратор открыл задачу в `ready`
- **THEN** видны план и его версия, изменённые файлы, тесты и кнопки приёмки

#### Scenario: Решение из панели
- **WHEN** администратор нажимает «Принять и опубликовать»
- **THEN** задача переходит в `merged` и экран показывает новый статус

#### Scenario: Ошибка задачи
- **WHEN** задача в `error`
- **THEN** видны текст ошибки, последние события и сохранённый checkpoint

### Requirement: Экран skills
Система SHALL показывать на `/skills` категории и карточки skills и SHALL
позволять создать категорию, создать и изменить skill, отключить его
и назначить агенту.

#### Scenario: Редактирование
- **WHEN** администратор изменил Markdown skill и сохранил
- **THEN** карточка показывает новую версию и хеш

#### Scenario: Назначение агенту
- **WHEN** администратор выбрал набор skills для агента
- **THEN** карточка агента показывает этот набор

### Requirement: Карточка агента
Система SHALL показывать имя агента, проект, статус, время heartbeat, Git remote,
назначенные skills и версии skills текущей задачи.

#### Scenario: Занятый агент
- **WHEN** агент выполняет задачу
- **THEN** карточка показывает `busy` и версии skills из снимка

### Requirement: Обновление без реального времени
Система SHALL обновлять данные опросом или перезагрузкой и SHALL не требовать
WebSocket-соединения.

#### Scenario: Статус изменился вне панели
- **WHEN** агент сменил статус задачи, пока панель открыта
- **THEN** после обновления панель показывает новый статус

### Requirement: Ограничение доступа к панели
Система SHALL требовать сессию администратора для всех экранов, кроме `/login`,
и SHALL не показывать данные проекта без неё.

#### Scenario: Прямой переход без входа
- **WHEN** на `/tasks/{id}` переходят без сессии
- **THEN** происходит редирект на `/login`
