# Spec Delta

## Purpose

Описывает проекты и агентов проекта: то, к чему привязываются задачи, skills
и подключение Harness.

## ADDED Requirements

### Requirement: Управление проектами
Система SHALL позволять администратору создавать проект, получать список проектов
и карточку проекта; проект SHALL содержать название, описание и привязанный
Telegram-чат.

#### Scenario: Создание проекта
- **WHEN** администратор отправляет название проекта
- **THEN** проект создаётся и доступен в списке

#### Scenario: Список проектов
- **WHEN** администратор открывает список
- **THEN** видны проекты с числом активных задач и агентами

#### Scenario: Проект без Telegram-чата
- **WHEN** проект создан без `telegram_chat_id`
- **THEN** проект создаётся, а сообщения из Telegram задачи в него не создают

### Requirement: Список агентов проекта
Система SHALL возвращать агентов проекта с именем, статусом, временем
последнего heartbeat и Git remote.

#### Scenario: Агент подключён
- **WHEN** администратор запрашивает агентов проекта после `harness init`
- **THEN** в ответе есть агент со статусом и временем heartbeat

#### Scenario: Агент не выходил на связь
- **WHEN** с последнего heartbeat прошло больше удвоенного TTL аренды
- **THEN** агент показывается как `offline`

### Requirement: Создание init-кода из карточки проекта
Система SHALL создавать новый init-код для проекта по запросу администратора
и возвращать его значение ровно один раз.

#### Scenario: Код выдан
- **WHEN** администратор нажимает «Подключить Harness»
- **THEN** сервер возвращает код и время его истечения

#### Scenario: Значение не раскрывается повторно
- **WHEN** администратор запрашивает карточку проекта позже
- **THEN** значение прежнего init-кода не возвращается

### Requirement: Статус агента отражает занятость
Система SHALL показывать агента как `busy`, пока у него арендованная задача,
и как `online` при живом heartbeat без задачи.

#### Scenario: Агент арендовал задачу
- **WHEN** агент получил задачу через claim
- **THEN** его статус становится `busy`

#### Scenario: Задача завершена
- **WHEN** задача перешла в `ready`, `error` или `trash`
- **THEN** агент снова показывается `online`
