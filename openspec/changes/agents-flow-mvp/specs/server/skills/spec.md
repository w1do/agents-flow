# Spec Delta

## Purpose

Хранит предметную логику работы в виде Markdown-инструкций, которые
назначаются конкретному агенту и фиксируются на задаче версией и хешем.

## ADDED Requirements

### Requirement: Категории skills
Система SHALL хранить категории как данные, позволяя создавать и переименовывать
их без изменения кода, и SHALL располагать их в заданном порядке.

#### Scenario: Создание категории
- **WHEN** администратор создаёт категорию с названием
- **THEN** категория доступна для привязки новых skills

#### Scenario: Новая предметная область
- **WHEN** администратор создаёт категорию «SEO» и skill в ней
- **THEN** skill доступен для назначения агенту без правок кода

### Requirement: Карточка skill
Система SHALL хранить skill с названием, категорией, описанием, Markdown-содержимым,
версией, хешем содержимого и признаком активности.

#### Scenario: Создание skill
- **WHEN** администратор создаёт skill с Markdown-текстом
- **THEN** skill сохраняется с версией 1 и хешем содержимого

#### Scenario: Чтение карточки
- **WHEN** администратор открывает skill
- **THEN** видны содержимое, версия, хеш и назначенные агенты

### Requirement: Версия и хеш при изменении текста
Система SHALL увеличивать версию skill на единицу и пересчитывать хеш при каждом
изменении содержимого, и SHALL не увеличивать версию при правке только описания.

#### Scenario: Изменение текста
- **WHEN** меняется Markdown-содержимое
- **THEN** версия увеличивается и хеш меняется

#### Scenario: Правка описания
- **WHEN** меняется только описание или название
- **THEN** версия остаётся прежней

### Requirement: Назначение skills агенту
Система SHALL назначать skills конкретному агенту и SHALL заменять набор
целиком по явному списку.

#### Scenario: Замена набора
- **WHEN** приходит список из четырёх skill id
- **THEN** у агента остаются только они

#### Scenario: Снятие skill
- **WHEN** skill отсутствует в новом списке
- **THEN** он больше не передаётся агенту в следующих задачах

#### Scenario: Skills не наследуются автоматически
- **WHEN** в проекте несколько агентов и создан новый skill
- **THEN** ни один агент не получает его без явного назначения

### Requirement: Архивирование skill
Система SHALL исключать архивированные skills из выдачи агентам, сохраняя
историю и ссылки в задачах.

#### Scenario: Skill архивирован
- **WHEN** администратор отключает skill
- **THEN** агент больше его не получает, а прошлые задачи сохраняют снимок

### Requirement: Снимок skills на задаче
Система SHALL фиксировать при аренде задачи набор skill-ов с названием, версией
и хешем, и SHALL не менять этот набор при последующей правке skills.

#### Scenario: Правка во время задачи
- **WHEN** skill изменён, пока задача в работе
- **THEN** текущая задача продолжает использовать зафиксированную версию

#### Scenario: Новая задача после правки
- **WHEN** создаётся и арендуется следующая задача
- **THEN** снимок содержит новую версию skill

### Requirement: Предупреждение о похожем на секрет содержимом
Система SHALL при сохранении skill находить паттерны, похожие на ключи, токены
и приватные ключи, и SHALL предупреждать администратора.

#### Scenario: В тексте найден токен
- **WHEN** содержимое skill содержит строку, похожую на приватный ключ
- **THEN** сохраняемый ответ содержит предупреждение с перечнем совпадений

#### Scenario: Предупреждение не логируется содержимым
- **WHEN** сработало предупреждение
- **THEN** в лог попадает только факт совпадения, без фрагмента секрета

### Requirement: Формат имени файла skill для Harness
Система SHALL отдавать Harness имя файла вида `<категория>--<название>.md`
в латинице со слагом и SHALL гарантировать уникальность имени в рамках агента.

#### Scenario: Выдача skills агенту
- **WHEN** Harness синхронизирует skills
- **THEN** каждый skill приходит с именем файла и содержимым

#### Scenario: Совпадение слагов
- **WHEN** два skills в разных категориях дают одинаковый слаг
- **THEN** имена файлов различаются добавлением суффикса и остаются уникальными
