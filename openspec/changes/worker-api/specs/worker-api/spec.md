# Spec Delta

## Purpose

Worker на машине агента работает через HTTP API сервера и не обращается к базе напрямую. Все операции
очереди задач, событий, статусов, чекпоинтов, итогов и heartbeat выполняются сервером.

## ADDED Requirements

### Requirement: Отдельный токен worker

Сервер SHALL принимать запросы worker только с worker-токеном, который задаётся в ENV сервера. Токен
MUST NOT совпадать с `HARNESS_ADMIN_TOKEN`. Worker-токен MUST NOT храниться в базе или логах в открытом виде.

#### Scenario: Запрос без worker-токена
- **WHEN** запрос к API worker пришёл без токена или с токеном оператора
- **THEN** сервер отвечает 401 без подробностей о том, какое условие не выполнено

#### Scenario: Неверный worker-токен
- **WHEN** запрос пришёл с неверным worker-токеном
- **THEN** сервер отвечает 401 без подробностей и не выполняет операцию

### Requirement: Захват задачи из очереди

Сервер SHALL отдавать worker задачу из очереди атомарно: одна задача не выдаётся двум worker. Ответ на
захват MUST содержать идентификатор задачи, проект, текст задачи и токен задачи для дальнейших вызовов. Токен
задачи MUST быть одноразовым для роли и MUST истекать по сроку, заданному сервером.

#### Scenario: Пустая очередь
- **WHEN** worker запрашивает задачу, а подходящих задач нет
- **THEN** сервер отвечает пустым результатом без ошибки

#### Scenario: Задача по отключённому проекту
- **WHEN** в очереди есть задача по проекту со статусом `disabled`
- **THEN** сервер не выдаёт такую задачу worker и не меняет её статус

### Requirement: Запись событий, статусов и итогов

Сервер SHALL принимать от worker события задачи, смену статуса (только переходы из `domain/statuses.py`),
чекпоинты и итог агента. Каждая запись MUST проверяться токеном задачи: задача из другого токена не
изменяется. Запись MUST быть идемпотентной по ключу события.

#### Scenario: Переход статуса вне таблицы
- **WHEN** worker пытается перевести задачу в статус, не разрешённый таблицей переходов
- **THEN** сервер отвечает 409 и не меняет статус

#### Scenario: Повторная отправка события
- **WHEN** worker повторно отправляет событие с тем же ключом
- **THEN** сервер не создаёт дубль и возвращает прежний результат

### Requirement: Heartbeat

Сервер SHALL принимать heartbeat worker по взятой задаче. Задача без heartbeat дольше срока MUST быть
переведена в статус `stalled` сервером, а не worker.

#### Scenario: Пропущенный heartbeat
- **WHEN** heartbeat не приходит дольше срока, заданного сервером
- **THEN** задача переходит в `stalled` и попадает в список для оператора

### Requirement: Ответы без секретов

Ответы API worker MUST NOT содержать значений ключей vault, токенов подписки, `DATABASE_URL` и
worker-токена. Ссылки `vault:...` допускаются, значения — нет.

#### Scenario: Ответ на захват задачи
- **WHEN** worker захватывает задачу
- **THEN** ответ содержит ссылку `access_ref`, но не содержит значение ключа

### Requirement: Учёт песочницы и восстановление через API

Сервер SHALL через worker API закреплять и восстанавливать песочницу, учитывать время и pid
агента и фазы очистки (D-41). Worker MUST выполнять команды локально без БД. Все операции MUST
проверять worker-токен; операции задачи — также токен задачи, кроме восстановления и продолжения
начатой очистки, которые проверяют закрепление.

#### Scenario: Первый запуск
- **WHEN** worker начинает запуск закреплённой задачи
- **THEN** сервер сохраняет время запуска до локального exec и разрешает запуск только по первому ключу
- **AND** после exec worker сохраняет pid через API

#### Scenario: Закрепление после захвата
- **WHEN** worker закрепляет захваченную задачу за свободной настроенной песочницей
- **THEN** сервер атомарно сохраняет закрепление; занятая другой задачей песочница даёт 409

#### Scenario: Восстановление после рестарта
- **WHEN** worker запрашивает восстановление настроенной песочницы с закреплённой задачей
- **THEN** сервер возвращает задачу, проект, время запуска и pid из БД, сохраняет действующие токены агента до очистки и выдаёт новый токен worker
- **AND** worker продолжает наблюдать прежний процесс без повторного запуска; если очистка уже начата, токен не перевыдаётся

#### Scenario: Повтор записи запуска
- **WHEN** время запуска уже записано и worker повторяет запрос с тем же ключом
- **THEN** сервер возвращает прежнюю запись; запрос с другим ключом не разрешает повторный запуск

#### Scenario: Очистка после задачи
- **WHEN** worker начинает очистку закреплённой задачи
- **THEN** сервер отзывает токены до локальных команд; повтор начала очистки безопасен
- **AND** при ошибке сервер сохраняет закрепление и ставит песочнице error; только успешная очистка и пауза освобождают её

#### Scenario: Чужая задача
- **WHEN** операция учёта запуска или очистки указывает другую задачу или песочницу
- **THEN** сервер отказывает без изменения записи
