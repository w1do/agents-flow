# Proposal

## Why

Worker сейчас читает очередь задач и пишет события, статусы и результаты напрямую в Postgres (`harness_server/worker/`, `services/tasks.py`, `services/sandboxes.py`). Поэтому worker можно запускать только рядом с базой, то есть на хосте сервера. Оператор хочет запускать worker на машине агента, где стоят `claude` и локальные репозитории, а сервер держать отдельно. Доступ к базе с машины агента открывать нельзя. Значит, worker должен работать через HTTP API сервера.

## What Changes

- Новый HTTP API для worker под отдельным worker-токеном (не `HARNESS_ADMIN_TOKEN`): захват задачи из очереди с выдачей токена задачи, запись событий и статусов, чекпоинтов и итога агента, heartbeat.
- Логика остаётся в `services/`. Эндпоинты тонкие: валидация Pydantic на входе, вызов сервиса, перевод доменных ошибок в ответы.
- Worker получает задачу и отчитывается через этот API. Прямой доступ worker к БД не используется.
- Ответы API не содержат секретов: значения ключей, токены подписки, `DATABASE_URL`.
- Worker-токен выдаётся и отзывается оператором через ENV сервера; в БД и логах он не хранится в открытом виде.

**BREAKING** для текущей схемы запуска: worker на хосте сервера переходит на API. Прямой доступ worker к базе будет убран после перехода.

## Capabilities

### New Capabilities
- `worker-api`: HTTP API сервера, через который worker захватывает задачи и отчитывается о ходе и итоге работы без доступа к базе.

### Modified Capabilities
- Нет. Поведение статусов задачи (`task-lifecycle`) и песочниц (`sandbox-runtime`) не меняется: меняется только канал, по которому worker до них дотягивается.

## Impact

- Сервер: новые эндпоинты в `apps/server/src/harness_server/api/` (префикс `/worker`), сервис `services/worker_api` или расширение существующих сервисов очереди.
- Worker: клиент API в `worker/` и `adapters/`, работающий через httpx; прямые импорты БД в worker убираются.
- Конфиг и ENV: `WORKER_API_TOKEN` (или аналог) на сервере и на машине агента; `DATABASE_URL` на машине агента не нужен.
- Зависит от: проекты на сервере (`GET /api/projects/{id}/settings`, уже есть, D-65).
- Не входит: консоль, Telegram-сценарии, перенос песочниц на машину агента, изменение логики планирования и проверок.
- Пример проверки: задача `chostotyumen` «Создай README.md с текстом Hello World» выполняется на машине агента без доступа к базе.
