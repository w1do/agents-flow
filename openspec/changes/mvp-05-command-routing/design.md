# Design: mvp-05-command-routing

## Context

Polza — шлюз к LLM; документация формата не проверена (D-17). Ответ модели — недоверенный вход.

## Goals / Non-Goals

**Goals:** класс и кандидаты за один вызов; детерминированный запасной путь; полная трассировка решения.

**Non-Goals:** выполнение действий моделью, мультиязычные синонимы проектов вне `voice_aliases`.

## Decisions

- **Один вызов с JSON-ответом** (`response_format: json_object`, при отказе модели — извлечение первого
  JSON-объекта из текста). Альтернатива — два вызова (класс, затем проекты): вдвое дороже и медленнее.
- **Модель только предлагает.** Сервер сам проверяет id workspace по конфигу и сам решает путь по классу.
- **Таймаут 10 с и одна повторная попытка**, затем запасной путь со всеми workspace.
- **Промпт — файл `services/prompts/routing.md`**, а не строка в коде; в нём список классов с примерами из ТЗ §5.0.
- **Ответ на `status`** формируется шаблоном из данных БД, без LLM: дешевле и без выдумок.

## Risks / Trade-offs

- [Модель путает «проверь» и «сделай»] → порог уверенности и кнопка уточнения; класс `work` при сомнении не стартует.
- [Распознавание названий проектов голосом] → `voice_aliases` в конфиге и в промпте; ручная проверка на реальных фразах (C5).
