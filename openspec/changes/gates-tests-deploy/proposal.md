# Proposal: gates-tests-deploy

> Гейты качества по workspace и задаче, деплой. Волна 4 (после MVP), см. PLAN.md. Следует D-58 «Гейты в три уровня».

## Why

Разные workspace требуют разных проверок: тексты — только проверку человеком, продукт — тесты и деплой (ТЗ §12).
В `mvp-09` есть базовые гейты безопасности (уровень 1, в коде, всегда) и гейты проекта с двумя пресетами `code` и
`none` и одной командой тестов (уровень 2). Этого мало для контента, данных и документации. Задача тоже должна
уметь потребовать больше проверок, но никогда меньше (D-58).

## What Changes

- **Пресеты уровня 2:** `content`, `data`, `docs` в дополнение к `code` и `none`. Пресет — шаблон набора гейтов
  проекта с переопределениями (`test`, `lint`, `build`, `check`), а не отдельный механизм.
- **Уровень задачи (уровень 3):** задача может добавить проверки (`extra_checks`) и потребовать приёмку владельцем
  (`require_owner_approval`). Убрать или ослабить гейт проекта или базовый гейт нельзя: итоговый набор —
  объединение уровней.
- **Файл гейтов в репозитории** (`.harness/gates.yaml`) читается только из основной ветки (`origin/<default_branch>`)
  и никогда — из ветки задачи. Он дополняет конфиг workspace по тем же правилам: добавляет проверки, но не убирает их.
- **Гейт деплоя:** команда деплоя в staging, пройден только при нулевом коде.
- **Тесты — отдельный процесс** с отчётом в Telegram (этап «тестирование»).

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `delivery-gates`: добавляются требования (ADDED): Пресеты гейтов проекта, Гейты задачи только добавляют, Файл
  гейтов из основной ветки, Гейт деплоя.

## Impact

- Зависит от: `processes` (тесты как процесс), `mvp-09-delivery-mr` (базовые гейты, `WorkspaceGates`, `PRESETS`).
  Для приёмки владельцем использует кнопку «Принять» из `mvp-09` и «Доработать» из `task-rework`.
- Ссылки: ТЗ §10 п.4, §12 (гейты workspace); D-56, D-58.
- Затрагивает ARCHITECTURE.md (гейты, конфиг §9) и, при новых инструментах, docs/mcp-agents-flow.md (параметры
  гейтов задачи в `create_task`).

## Не входит

- Изменение базовых гейтов безопасности: они в коде и не настраиваются (D-58).
- Настройка гейтов в консоли — после `workspace-settings-snapshot` и консоли.
- Авто-мердж (`staging-auto-merge`).
