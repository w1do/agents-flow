## ADDED Requirements

### Requirement: Пресеты гейтов проекта

Гейты качества проекта SHALL задаваться пресетом workspace (`code`, `content`, `data`, `docs`, `none`) с
переопределениями команд. Пресет MUST быть шаблоном набора гейтов, а не отдельным механизмом. Базовые гейты
безопасности MUST выполняться при любом пресете. Гейт без нужной команды MUST NOT считаться пройденным и SHALL
требовать решения владельца.

#### Scenario: Пресет контента

- **WHEN** у workspace пресет `content`
- **THEN** тесты не запускаются, базовые гейты выполняются, задачу принимает владелец кнопкой «Принять»

### Requirement: Гейты задачи только добавляют

Задача SHALL уметь добавить проверки и потребовать приёмку владельцем. Итоговый набор гейтов MUST быть объединением
базовых гейтов, гейтов проекта, файла гейтов репозитория и гейтов задачи. Убрать или ослабить гейт MUST быть
невозможно. Роль `implementer` MUST NOT задавать гейты своей задачи.

#### Scenario: Задача пытается убрать тесты

- **WHEN** в параметрах задачи передано поле отключения тестов
- **THEN** параметры отклоняются с `invalid_input`, тесты проекта выполняются

### Requirement: Файл гейтов из основной ветки

Файл гейтов в репозитории SHALL читаться только из основной ветки workspace и MUST NOT читаться из ветки задачи.
Он может только добавлять гейты.

#### Scenario: Файл гейтов изменён в ветке задачи

- **WHEN** агент изменил `.harness/gates.yaml` в ветке задачи
- **THEN** доставка останавливается базовым гейтом запрещённых путей, гейты берутся из файла основной ветки

### Requirement: Гейт деплоя

Гейт `deploy` SHALL выполнять команду деплоя в staging и считаться пройденным только по нулевому коду.

#### Scenario: Деплой упал

- **WHEN** команда деплоя вернула ошибку
- **THEN** задача в `error` с причиной, MR не помечается готовым
