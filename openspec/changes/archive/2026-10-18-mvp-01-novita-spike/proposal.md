# Proposal: mvp-01-novita-spike

## Why

Весь путь MVP держится на песочнице Novita: exec-команды, запись файлов, пауза с сохранением состояния,
возобновление и таймаут. Публичные источники противоречат друг другу о pause/resume (D-16), а риск A1 ТЗ
требует проверить это до любой другой работы. Если пауза не сохраняет файлы, меняется архитектура
песочницы, поэтому спайк идёт первым.

## What Changes

- Скрипт проверки `tools/spikes/novita_check.py` (Python SDK Novita, ключ из ENV), который на тестовой песочнице
  проверяет: создание, `exec` (код возврата, stdout/stderr, фоновый процесс), запись и чтение файла,
  пауза → возобновление с сохранением файла и фонового процесса, продление таймаута, поведение после таймаута.
- Отчёт `docs/novita.md`: что подтверждено, точные вызовы SDK, ограничения, цена паузы, кастомные образы (вопросы 5–7 ТЗ).
- Проверка `claude` CLI в песочнице: установка pinned-версии, `claude -p --output-format stream-json --verbose`,
  наличие `--max-turns` и `--bare` (ТЗ §10.1 «что проверить»), запись usage в файл.
- Обновление `docs/decisions.md` и `docs/open-questions.md` по итогам.

## Capabilities

### New Capabilities

Нет. Спайк не меняет поведение системы (`skip_specs: true`); его результат — документ и решения,
на которые опирается `mvp-06-sandbox-runtime`.

### Modified Capabilities

Нет.

## Impact

- Новые файлы: `tools/spikes/novita_check.py`, `docs/novita.md`.
- Зависимости: Python SDK Novita только для спайка (в сервер попадёт в `mvp-06`).
- Расход: несколько минут работы одной тестовой песочницы; песочница удаляется в конце скрипта.
- Ссылки: ТЗ §9, §10, §16.0 п.1, §16.1 A1, §17 вопросы 5–7.

## Не входит

Адаптер `SandboxProvider`, bootstrap-скрипт, запуск агента по задаче — это `mvp-06-sandbox-runtime`.
