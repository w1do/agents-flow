## Requirements

### Requirement: Только владелец и подписанный webhook

Сервер SHALL принимать обновления Telegram только с верным секретом webhook и только из чата `TELEGRAM_CHAT_ID`.
Запрос без верного секрета MUST получать `401`. Сообщения из других чатов MUST игнорироваться без ответа
пользователю и без сохранения их текста.

#### Scenario: Неверный секрет

- **WHEN** на webhook приходит запрос с неверным `X-Telegram-Bot-Api-Secret-Token`
- **THEN** сервер отвечает `401` и ничего не создаёт

#### Scenario: Чужой чат

- **WHEN** приходит сообщение из чата, отличного от владельца
- **THEN** сервер отвечает `200`, бот ничего не отправляет, задача не создаётся и в `telegram_updates` ничего
  не записывается

### Requirement: Идемпотентный приём

Повторная доставка обновления с тем же `update_id` и повторное нажатие кнопки с тем же `callback_query.id`
MUST NOT создавать новую задачу, новую активацию или новое событие.

#### Scenario: Повторная доставка

- **WHEN** Telegram дважды присылает одно обновление с текстом задачи
- **THEN** создаётся ровно одна задача

#### Scenario: Повторное нажатие кнопки

- **WHEN** Telegram дважды присылает нажатие кнопки с одним `callback_query.id`
- **THEN** статус меняется один раз, в ленте одно событие `planning`, ответ на нажатие отправляется один раз

### Requirement: Восстановление после рестарта

Принятое обновление владельца SHALL сохраняться до обработки вместе с нормализованным содержимым
(`telegram_updates.payload`). Worker при старте MUST дообработать обновления, у которых `processed_at` пуст и
которые получены больше минуты назад, и дослать карточку задаче `choosing` без сообщения. После обработки
содержимое обновления MUST удаляться (`payload = NULL`), а сохранённое содержимое MUST NOT включать данные
отправителя (имя, username).

#### Scenario: Апдейт принят перед рестартом

- **WHEN** webhook записал обновление с текстом задачи, а процесс остановился до обработки, и через минуту
  стартует worker
- **THEN** задача создаётся в `choosing`, обновление помечается обработанным, его содержимое удалено

#### Scenario: Содержимое удаляется после обработки

- **WHEN** обновление с текстом задачи обработано
- **THEN** у строки `telegram_updates` заполнен `processed_at`, а `payload` пуст

### Requirement: Только сообщения-задачи

Текст, начинающийся с `/`, и обновления без текста, голоса или нажатия кнопки (правка сообщения, стикер, фото)
MUST NOT создавать задачу и MUST NOT сохраняться.

#### Scenario: Команда /start

- **WHEN** владелец отправляет `/start`
- **THEN** сервер отвечает `200`, задача не создаётся, бот ничего не отправляет

### Requirement: Выбор проекта кнопкой

Текст, который маршрутизатор отнёс к классу `work` (уверенно, после кнопки «Сделать задачу» или по запасному пути),
SHALL создавать задачу `plan` в статусе `choosing` и сообщение с кнопкой на каждый предложенный workspace: не больше
трёх, самый вероятный первым, а при запасном пути — все workspace из `harness.yaml`. Нажатие кнопки MUST переводить
задачу в `planning` с выбранным workspace и записывать выбор в `routings`. Задача MUST NOT запускаться без нажатия.

#### Scenario: Выбор workspace

- **WHEN** владелец пишет «добавь экспорт в CSV» и нажимает кнопку проекта «Магазин»
- **THEN** задача получает workspace «Магазин» и статус `planning`, в сообщении появляется строка этапа

#### Scenario: Повторное нажатие после выбора

- **WHEN** владелец нажимает другую кнопку проекта у задачи уже в `planning`
- **THEN** workspace не меняется, бот отвечает подсказкой «проект уже выбран»

#### Scenario: Кнопка неизвестного проекта

- **WHEN** приходит нажатие кнопки с workspace, которого нет в `harness.yaml`
- **THEN** статус задачи не меняется, бот отвечает подсказкой «проект не найден»

#### Scenario: Выбор записывается в решение маршрутизации

- **WHEN** владелец нажимает кнопку проекта «Демо-проект» у задачи, созданной по запасному пути
- **THEN** в `routings` этой задачи `chosen_workspace_id` равен `demo`

### Requirement: Одно сообщение на задачу

Этапы задачи SHALL отображаться в одном сообщении, которое редактируется; каждая новая строка имеет вид
`Задача [<краткое название>] (<этап>)`, где краткое название — первая непустая строка текста задачи не длиннее
40 символов. Текст, уходящий в Telegram, MUST проходить фильтр секретов. Если сообщение нельзя
отредактировать, система SHALL отправить новое сообщение со всеми строками и дальше редактировать его.

#### Scenario: Два этапа

- **WHEN** задача переходит в «начата», а затем в «готова, MR создан»
- **THEN** в чате одно сообщение с двумя строками этапов

#### Scenario: Сообщение недоступно для правки

- **WHEN** Telegram отвечает, что сообщение задачи нельзя отредактировать
- **THEN** бот отправляет новое сообщение со всеми строками этапов, и следующие этапы дописываются в него

#### Scenario: Секрет в тексте

- **WHEN** текст, уходящий в сообщение задачи, содержит значение секрета из настроек
- **THEN** в Telegram вместо значения уходит `[REDACTED]`
