## Requirements

### Requirement: Активация песочницы под задачу

Перед запуском агента система SHALL возобновить песочницу, закрепить её за задачей, обновить репозиторий и создать
worktree на ветке `task/<task_id>` от указанной базы. Закрепление песочницы и выбор задачи MUST выполняться одной
транзакцией. Повторная активация той же задачи MUST возвращать текущее состояние без повторной подготовки.
Песочница MUST NOT закрепляться за двумя задачами одновременно. Песочница в статусе `error` MUST NOT брать задачи.

#### Scenario: Песочница занята

- **WHEN** песочница выполняет задачу A, а в очереди задача B
- **THEN** задача B остаётся в очереди в прежнем статусе, пока песочница не освободится

#### Scenario: Повторная активация

- **WHEN** worker перезапустился и снова активирует ту же задачу
- **THEN** worktree и ветка не пересоздаются, агент не запускается второй раз

#### Scenario: Песочница в ошибке

- **WHEN** песочница в статусе `error`, а в очереди есть задача
- **THEN** задача остаётся в очереди, песочница не возобновляется

### Requirement: Запуск агента без клиента

Агент SHALL запускаться командой в песочнице через API провайдера, в фоне, с выводом в файл потока и итогом
в файл статуса. Время запуска и pid агента MUST храниться на сервере, а не читаться из файлов песочницы. Токен задачи
SHALL выдаваться непосредственно перед запуском и храниться в БД только хешем; отмена worker MUST NOT отзывать токен
работающего агента.

#### Scenario: Превышено время

- **WHEN** агент работает дольше лимита времени задачи, считая от записанного времени запуска
- **THEN** группа процессов агента останавливается, задача переходит в `error` с причиной «превышено время»

#### Scenario: Рестарт worker во время работы агента

- **WHEN** worker остановлен и перезапущен, пока агент работает
- **THEN** агент не запускается повторно, его токен не отозван, таймаут отсчитывается от времени запуска в БД

### Requirement: Итог агента и его завершение

Сервер MUST считать агента завершённым только когда группы процессов агента нет; код выхода берётся из файла
статуса, итог хода — из события `result` в файле потока. Итог с исчерпанным лимитом подписки MUST NOT считаться
успешным завершением работы.

#### Scenario: Агент завершился

- **WHEN** процесс агента завершился с кодом 0
- **THEN** сервер читает статус и событие `result`, сохраняет код выхода и переходит к следующему этапу задачи

#### Scenario: Агент пропал без статуса

- **WHEN** pid агента известен серверу, группы процессов нет и файла статуса нет
- **THEN** задача переходит в `error` с причиной «агент завершился без статуса», повторного запуска нет

#### Scenario: Статус записан при живом агенте

- **WHEN** файл статуса есть, а группа процессов агента ещё жива
- **THEN** агент считается работающим, таймаут отсчитывается от времени запуска, сохранённого на сервере

#### Scenario: Исчерпан лимит подписки Claude

- **WHEN** итог хода в файле потока сообщает об исчерпанном лимите подписки (один ход или ошибка), а код выхода 0
- **THEN** агент считается неуспешным, задача переходит в `error` с причиной `usage_limit`, текст лимита не попадает в ленту, повторного запуска нет

### Requirement: Изоляция агента от настроек репозитория

Агент SHALL запускаться без чтения hooks и MCP-серверов из настроек проекта в рабочем каталоге: только
пользовательские настройки чистого профиля песочницы и MCP-конфигурация харнесса. Переменные `ANTHROPIC_API_KEY`
и `ANTHROPIC_AUTH_TOKEN` MUST NOT передаваться процессу агента.

#### Scenario: Hook в репозитории

- **WHEN** в worktree лежит `.claude/settings.json` с hook и `.mcp.json` с посторонним сервером
- **THEN** hook не выполняется, посторонний сервер не подключается

### Requirement: Креды не остаются в песочнице

Секреты SHALL передаваться в песочницу только в окружении конкретной команды и MUST NOT записываться в файлы
песочницы. Это касается и ключей из vault: они передаются в env bootstrap, активации и запуска агента.
Bootstrap-скрипт и файлы запуска агента MUST NOT содержать секретов. Текст, прочитанный из песочницы, MUST проходить
redaction, в том числе по значениям из vault, до записи в лог, БД или Telegram.

#### Scenario: Проверка диска

- **WHEN** после запуска агента в песочнице ищут значение выданного токена в `~` и в каталоге репозитория
- **THEN** значение не найдено

#### Scenario: Секрет в выводе агента

- **WHEN** `stderr.log` агента содержит значение OAuth-токена
- **THEN** в лог и БД уходит текст с `[REDACTED]` вместо значения

#### Scenario: Токен задачи после рестарта worker

- **WHEN** `stderr.log` агента содержит токен задачи, а worker, выдавший токен, перезапущен
- **THEN** токен заменяется на `[REDACTED]` по шаблону формата токена задачи

#### Scenario: Ключ из vault в выводе

- **WHEN** вывод bootstrap, активации или агента содержит значение ключа из vault
- **THEN** в лог и БД уходит текст с `[REDACTED]` вместо значения

### Requirement: Пауза только после очистки

После завершения задачи система SHALL удалить worktree, локальную ветку и каталог файлов задачи, отозвать токены задачи и только при
успехе очистки поставить песочницу на паузу и освободить её. При ошибке очистки песочница MUST переходить в `error`
без паузы.

#### Scenario: Очистка не удалась

- **WHEN** удаление worktree вернуло ненулевой код
- **THEN** песочница в статусе `error`, пауза не вызывается, причина записана

#### Scenario: Успешная очистка

- **WHEN** задача завершилась и очистка прошла
- **THEN** токены задачи отозваны, песочница на паузе, `current_task_id` пуст

### Requirement: Ручная пауза и возобновление

Оператор SHALL иметь одну команду для паузы и одну для возобновления песочницы из конфигурации, а также команду
статуса и подготовки (bootstrap). Пауза MUST отказывать, если за песочницей закреплена активная задача.

#### Scenario: Пауза занятой песочницы

- **WHEN** оператор вызывает паузу во время активной задачи
- **THEN** команда отказывает с указанием задачи

#### Scenario: Возобновление песочницы в ошибке

- **WHEN** оператор вызывает возобновление песочницы в статусе `error` без закреплённой задачи
- **THEN** песочница проверяется подключением, ставится на паузу у провайдера и получает статус `paused`

#### Scenario: Возобновление свободной песочницы

- **WHEN** оператор вызывает возобновление песочницы в статусе `paused`
- **THEN** статус не меняется, провайдер не вызывается

#### Scenario: Повторный bootstrap

- **WHEN** bootstrap запускается второй раз на подготовленной песочнице
- **THEN** скрипт завершается с кодом 0, репозитории не клонируются заново, версии не переустанавливаются
