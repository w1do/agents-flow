# Жизненный цикл задачи

## Статусы

| Статус | Значение |
|---|---|
| `new` | создана, ждёт агента |
| `choosing` | агент арендовал, готовит запуск |
| `planning` | агент формирует или улучшает план |
| `backlog` | план ждёт решения пользователя |
| `active` | план подтверждён, идёт реализация |
| `testing` | агент запускает проверки из skills |
| `ready` | результат ждёт приёмки |
| `merged` | принят, разрешена публикация |
| `error` | техническая ошибка |
| `stalled` | аренда истекла |
| `paused` | остановлена пользователем |
| `trash` | убрана из работы |

## Переходы

```
new → choosing → planning → backlog → active → testing → ready → merged
```

| Переход | Кто инициирует |
|---|---|
| `backlog → planning` | пользователь: «Улучши план» |
| `ready → active` | пользователь: «Доработать» |
| любой рабочий → `paused` | пользователь |
| любой рабочий → `error` | агент через `fail` |
| нет heartbeat по истечении аренды → `stalled` | сервер |
| `stalled → new` | только администратор |
| любой → `trash` | пользователь |

Правила:

- `merged` ставит только сервер по решению `publish`. Агент не может.
- `approved` по плану — только пользователь; агент видит результат, но не меняет.
- `keep_ready` оставляет задачу в `ready`, публикация не запускается.
- Ошибка публикации после `merged` не откатывает статус: пишется событие.

## Аренда

- Harness опрашивает каждые 5 секунд.
- Один агент — не больше одной задачи.
- Задача выбирается из своего проекта со статусом `new`.
- Транзакция: `SELECT ... FOR UPDATE SKIP LOCKED`.
- Записываются `assigned_agent_id`, `lease_id`, `lease_expires_at` (+60 с).
- Heartbeat продлевает аренду на 60 секунд.
- Все отчёты несут `lease_id`; чужой или старый — `409`.
- Истёкшая аренда → `stalled`, возвращает администратор.

## Идемпотентность

- REST: заголовок `Idempotency-Key`, таблица `idempotency_keys`,
  уникальность `scope + idempotency_key`.
- Повтор возвращает сохранённый ответ, дубликата не создаёт.
- MCP: обязательный `event_id` на каждый отчёт.
- Повтор события с тем же `event_id` игнорируется.

## Снимок skills

При аренде задачи сервер фиксирует `task_skill_snapshots`:
название, версия, хеш, категория. Правка skill во время работы задачи
не влияет на текущую — новая версия применяется со следующей задачи.
