# Roadmap MVP

Порядок, в котором собираем систему. Каждый шаг заканчивается работающим куском,
а не заготовкой.

## Шаг 1. Каркас сервера

- FastAPI, настройки, подключение к PostgreSQL, Alembic.
- Модели: `users`, `projects`, `project_init_tokens`, `agents`.
- `POST /auth/login`, CRUD проектов.
- Первый администратор из окружения.

Готово, когда: сервер поднимается в Compose, миграции применяются, логин работает.

## Шаг 2. Skills

- `skill_categories`, `skills`, `agent_skills`.
- API категорий, skills, назначение агенту.
- Версии, хеш, архивирование.

Готово, когда: в API можно создать skill и назначить агенту.

## Шаг 3. Задачи и аренда

- `tasks`, `task_events`, `task_skill_snapshots`, `idempotency_keys`.
- Аренда с `FOR UPDATE SKIP LOCKED`, heartbeat, TTL.
- `POST /harness/init` и Harness API.

Готово, когда: тестовый клиент арендует задачу и продлевает аренду.

## Шаг 4. Harness

- `init`: Git-корень, remote, конфиг, skills, `.agent-token`.
- `run`: цикл аренды, worktree, синхронизация skills, heartbeat.
- Запуск Deep Agents и передача плана/результата.

Готово, когда: бинарник в тестовом репозитории проходит путь до `backlog`.

## Шаг 5. Решения пользователя

- `plan/decision`, `result/decision`.
- Переходы `backlog → active`, `ready → active/merged/ready`.
- Events для каждого решения.

Готово, когда: план можно улучшать, а результат — принимать и возвращать.

## Шаг 6. Telegram

- Текст, voice, audio; транскрибация; создание задачи.
- Кнопки решений и уведомления.

Готово, когда: голосовая задача доходит до плана и приёмки без терминала.

## Шаг 7. Панель

- 5 экранов: `/login`, `/projects`, `/projects/{id}`, `/tasks/{id}`, `/skills`.
- Карточка агента: статус, heartbeat, remote, skills и версии.

Готово, когда: весь ход задачи виден в панели.

## Шаг 8. MCP

- 11 инструментов поверх общих сервисов.
- `event_id`, проверка lease, ограничения прав.

Готово, когда: агент может отчитаться через MCP вместо REST.

## Шаг 9. Публикация

- Skills git и deploy на этапе `publish`.
- Итог публикации, события, отчёт.

Готово, когда: push и Dokploy запускаются только после решения пользователя.

## Шаг 10. Приёмка

- Прогон сценария из MVP.md на реальном репозитории.
- Проверки из docs/criteria.md и docs/security.md.

Готово, когда: все 20 приёмочных критериев выполнены.

## После MVP

Не раньше, чем MVP принят:

- несколько агентов на проект;
- шаблоны skills;
- библиотека skills для новых областей (SEO, контент, аналитика);
- WebSocket-обновления панели;
- роли и команды.
