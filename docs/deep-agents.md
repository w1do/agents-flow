# Deep Agents в Agents Flow

Готовый движок агента. Harness его не заменяет и не переписывает —
только запускает и передаёт входные данные.

## Что получает агент

| Данные | Когда |
|---|---|
| текст задачи | всегда |
| путь к локальному проекту | всегда |
| worktree и ветка `task/<task_id>` | реализация |
| skills текущего этапа | по этапу |
| checkpoint | при возобновлении |
| решения пользователя | после плана и результата |

## Этапы

### 1. Планирование

Вход: задача, путь, skills разработки/ресёрча, проектные инструкции.
Выход: `plan_text`.
Агенту запрещено менять файлы на этом этапе.

### 2. Реализация

Вход: утверждённый план, skills разработки и тестирования, фидбек при доработке.
Выход: изменения в worktree, черновик отчёта.

### 3. Проверки

Вход: skills тестирования.
Выход: `result_data.tests` — команды, exit code, краткая сводка.

### 4. Публикация

Вход: skills git и деплоя, только после решения `publish`.
Выход: SHA, remote, результат деплоя.

## Отчёт

Обязательные части:

- краткий итог;
- изменённые файлы;
- результаты проверок;
- commit SHA, если skill его создал;
- готовность к публикации;
- известные риски.

## Ограничения

- Работа только в worktree задачи, вне основной ветки.
- Непривилегированный пользователь.
- Нет Docker socket, домашнего каталога, SSH-ключей, production-доступа
  по умолчанию.
- Нет права менять статусы, подтверждать план, принимать результат.
- Секреты не читает и не пишет.

## Передача управления

Агент не ждёт в процессе: он завершает шаг, а Harness опрашивает сервер
и продолжает работу, когда появилось решение. Так обрыв связи не убивает задачу.
