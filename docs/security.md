# Безопасность

## Токены

| Токен | Срок | Хранение | Права |
|---|---|---|---|
| init-код | 10 минут, один раз | хеш в `project_init_tokens` | только `POST /harness/init` |
| agent token | до отзыва | хеш в `agents` | свой проект, своя задача |
| JWT панели | сессия | не в БД | администратор проекта |
| Telegram webhook | постоянно | `TELEGRAM_WEBHOOK_SECRET` | приём сообщений |

Всё остальное — только хеши. Значения показываются один раз при создании.

## Права агента

Может: арендовать задачу своего проекта, продлевать аренду, отчитываться.
Не может: видеть чужие проекты, подтверждать план, принимать результат,
менять статус на `merged`, публиковать без решения пользователя.

## Публикация

- `publish` — единственный вход в этап публикации.
- Skills git/deploy передаются только после этого решения.
- Dokploy — webhook конкретного приложения, не административный ключ.
- Ошибка публикации — событие, а не откат статуса.

## Изоляция работы

- Отдельный Git worktree, ветка `task/<task_id>`.
- Непривилегированный пользователь.
- Нет Docker socket, `~`, SSH-ключей, production-доступа по умолчанию.
- Доступ к инструментам — только если это требуется назначенными skills.

## Секреты

Не хранятся: в skills, Git, YAML, логах, отчётах, event payload, Telegram.
Находятся: только в окружении Dokploy и `workflow/.agent-token` (0600).

При правке skill сервер предупреждает о похожих на секреты паттернах.

## Сеть

- Только HTTPS/TLS.
- PostgreSQL не публикуется наружу.
- `project_id` не секрет и сам по себе доступа не даёт.

При прямом доступе Uvicorn запускается без `--proxy-headers`. За обратным
прокси передавайте `--forwarded-allow-ips` только с адресом доверенного прокси;
прокси должен перезаписывать `X-Forwarded-For`, а не дописывать входное
значение. Приложение не разбирает этот заголовок вручную. `TRUSTED_PROXY_IPS`
используйте только при запуске Uvicorn: передайте значение в
`--forwarded-allow-ips`; само приложение не использует эту настройку при
обработке запросов.

## Логи

- Не пишутся: токены, тела init-запросов, содержимое skills, файлы `.env`.
- Пишутся: id задач, типы событий, коды ошибок.

## Проверки перед релизом

1. `grep` по репозиторию и логам — нет токенов.
2. Попытка чтения чужой задачи → 403/404.
3. Попытка `merged` агентом → отказ.
4. Повтор init-кода → отказ.
5. Публикация без `publish` → отказ.
