# Telegram

## Входы

- текстовое сообщение → `source_type = telegram_text`;
- voice → скачивание → транскрибация → `telegram_voice`;
- audio → то же, что voice.

## Голосовой поток

1. Webhook приходит в FastAPI.
2. Для голоса запрашивается файл у Telegram.
3. Файл скачивается во временный каталог.
4. Отправляется провайдеру транскрибации.
5. При успехе создаётся задача: `source_text` = распознанный текст,
   `description` = он же, `status = new`, заголовок — первые 120 символов.
6. После коммита бот присылает «Задача создана» с распознанным текстом
   и ссылкой на задачу в панели.
7. Временный файл удаляется всегда.

Ошибка транскрибации: задача не создаётся, бот просит повторить или написать
текстом. Временные файлы чистятся и при ошибке.

## Кнопки

План:

```
✅ Приступай        → plan/decision approved
✏️ Улучши план      → plan/decision rejected + feedback → planning
🛑 Отклонить        → задача в trash
```

Результат:

```
✅ Принять и опубликовать → result/decision publish
✏️ Доработать             → result/decision rework
⏸ Оставить без публикации → result/decision keep_ready
```

## Уведомления

- распознанный текст голосовой задачи;
- план с кнопками;
- старт работы;
- отчёт о готовой реализации;
- запрос на приёмку;
- общий итог публикации (`publication-result.success`);
- ошибка или потеря связи.

Отдельные уведомления об итогах push и deploy в этой группе не реализованы.

## Правила

- Сообщения короткие, человеческим языком, со следующим шагом.
- Текст задачи и отчёт обрезаются до разумной длины, полный текст — в панели.
- Секреты, токены, содержимое `.env` в Telegram не попадают.
- Webhook защищён `TELEGRAM_WEBHOOK_SECRET`.
- `telegram_chat_id` привязан к проекту: чужие чаты задачи не создают.

## Транскрибация

Провайдер выбирается `TRANSCRIPTION_PROVIDER`, ключ — `TRANSCRIPTION_API_KEY`.
Абстракция: `transcribe(file) -> text`. Новый провайдер добавляется без правок
обработчика сообщений.

## Ошибки

| Ситуация | Поведение |
|---|---|
| транскрибация упала | задача не создаётся, просьба повторить |
| файл слишком большой | отказ с понятным текстом |
| неизвестный чат | игнор + запись в лог без содержимого |
| Telegram недоступен | до четырёх попыток уведомления с backoff; события остаются в панели |

## Настройка и ограничения MVP

Webhook: `POST /api/v1/telegram/webhook`, заголовок
`X-Telegram-Bot-Api-Secret-Token` должен совпадать с `TELEGRAM_WEBHOOK_SECRET`.
Пустой секрет запрещает приём (401). Тело ограничено 1 МиБ: превышение даёт
413 по `Content-Length` до чтения или во время чтения потока; некорректный
update — 422 без деталей валидации. Без `TELEGRAM_BOT_TOKEN` маршрута нет;
REST и MCP работают. Автоматическая регистрация webhook не выполняется.

Bot API вызывается через `httpx`, без Telegram SDK. Аудио ограничено 20 МиБ
как по метаданным, так и при потоковом скачивании. Одновременно выполняются
не более двух аудиозапросов и не более одного на чат; превышение и общий
дедлайн в 120 секунд на скачивание с распознаванием дают понятный отказ без
создания задачи.
Временный файл удаляется
в `finally`, включая отмену запроса во время скачивания или распознавания.

`stub` возвращает «Тестовая голосовая задача». `openai` использует
`OPENAI_BASE_URL` (по умолчанию `https://api.openai.com/v1`),
`TRANSCRIPTION_API_KEY` с резервным `OPENAI_API_KEY` и
`TRANSCRIPTION_MODEL` (по умолчанию `whisper-1`). Требуется HTTPS, включая loopback.
Ответ провайдера ограничен 1 МиБ; распознанный текст сохраняется полностью,
усекается только уведомление. Ошибка настройки отклоняет
только голосовой ввод, сервер продолжает работать.

«Улучши план» и «Доработать» запрашивают замечание ответом на сообщение бота.
Ответ привязан к чату, пользователю, сообщению и задаче на 15 минут;
после истечения срока или рестарта нужно снова нажать кнопку.
Неудачная или отменённая отправка запроса замечания освобождает кнопку;
повтор webhook может снова запросить замечание. Feedback погашается после коммита.
Вытеснение feedback при переполнении (2000 записей) освобождает резерв кнопки
синхронно; можно снова нажать кнопку и отправить замечание.
После `keep_ready` выдаются новые кнопки; прежние кнопки и замечания недействительны.
При неоднозначной привязке одного чата к нескольким проектам update игнорируется.

Одновременно принимаются до 16 update; переполнение получает 503 без ожидания.
`update_id` и ответ webhook хранятся 24 часа в существующей таблице `idempotency_keys`,
в одной транзакции с изменениями задачи. Вытеснение из кэша и рестарт не снимают дедупликацию.
Параллельная доставка занятого update получает 503 для повторной попытки.
Обработка рассчитана на один процесс: резервы кнопок и feedback остаются в памяти.

Уведомления формируются тонким сервисом из событий существующих сервисов
задач, отчётов и решений, отправляются только после коммита, в том числе для MCP.
Очередь процесса вмещает 256 уведомлений, включая активные и отложенные,
но не более 16 на чат. Один чат не может занять всю очередь: остальные чаты
принимаются до общего предела. Переполнение квоты чата или общей ёмкости
отклоняет новое уведомление и логируется как `telegram_notification_chat_quota_full`
или `telegram_notification_queue_full`, без идентификаторов, текста и секретов.
История остаётся в панели; рестарт теряет очередь. Ошибка Telegram не меняет REST/MCP-ответ.
Повторы сохраняют `retry_after`, в том числе более 120 секунд; без него backoff —
0,25 / 0,5 / 1 секунда. Чаты обслуживаются независимо, порядок внутри чата сохраняется.
Лимит сохраняется до своего срока даже после последней попытки и опустошения очереди чата.
Bot API [не сообщает область лимита](https://core.telegram.org/bots/api#responseparameters):
для обычного `sendMessage` пауза относится к чату, остальные чаты продолжают
отправку. Планировщик умеет и общую область бота, но текущий клиент её не выдаёт.
Доступ к 16 слотам отправки — FIFO, один исполнитель на чат.
Bot API и одна попытка доставки имеют общий дедлайн по 30 секунд после получения слота;
до четырёх попыток занимают до 120 секунд исполнения, отдельно от отложенного ожидания.
Ожидание слота не расходует дедлайн и число попыток.
Сообщения ограничены 3500 единицами UTF-16 с пометкой об усечении и ссылкой
`PUBLIC_BASE_URL/tasks/{id}`. Ошибки передаются стандартным человеческим текстом;
конфигурация, известные секреты и похожие на токены фрагменты скрываются.
HTTP-логи `httpx`/`httpcore` ограничиваются уровнем WARNING при внешних вызовах,
чтобы URL Bot API и заголовки авторизации не попадали в INFO/DEBUG.
