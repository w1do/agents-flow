# Граница секретов runner (MVP)

1. Доверяем процессу runner, harness, ядру Linux, bwrap и системным `/usr`, `/lib*`, `/bin`, `/sbin`.
2. Модель, ответы SDK, skill-программы и файлы worktree считаются недоверенными.
3. Config одним чтением env-file объединяет его с env; тот же набор создаёт immutable-снимок секретов.
4. Явный `config.reload()` создаёт новое поколение; маскирование хранит и предыдущие поколения до выхода.
5. Агент получает очищенные task/skills/файлы и только проверенные list/read/write-действия.
6. SDK очищает запрос и ответ каждого внутреннего model turn, включая повторы запрещённых tool calls.
   Исходный путь последнего JSON-действия хранится отдельно в доверенной памяти middleware/adapter,
   до очистки SDK-ответа. Модель, история, JSON и события получают только очищенный текст;
   исходная идентичность передаётся напрямую распределителю путей runner. Если соответствие
   очищенному SDK-ответу потеряно, файловое действие отклоняется до исполнения.
7. Shell получает текст skill, разрешённое окружение и приватную очищенную копию worktree.
8. `.env*`, `.agent-token`, `.git` любого типа исключаются целиком на каждом уровне копирования.
9. Поиск, открытие и bind используют закреплённые fd; shell не получает live bind исходного worktree.
   Проекция передаётся через потребляемый `bwrap --bind-fd`, а не pathname `/proc/self/fd/N`.
   Bwrap закрывает mount-fd и seccomp-fd до exec команды; остальные host-fd закрывает Popen.
   Команда наследует только stdin/stdout/stderr на `/dev/null`, без host-dirfd для openat("..").
10. Sandbox-изоляция — основной барьер; redaction — защита в глубину.
    Отдельные mount/PID/IPC namespaces закрывают host-файлы, процессы и SysV SHM/очереди/семафоры;
    `/tmp`, `/home`, `/run`, `/dev/shm` приватны. Capabilities сброшены, новая сессия обязательна.
    Seccomp запрещает socket/socketpair/io_uring_setup (включая socketcall на i386 и x32 на x86_64).
    Нет унаследованных сокетов; pathname/abstract Unix sockets и сетевые сокеты недоступны.
11. Артефакты — все имена, каталоги и обычные файлы выставленного дерева, включая неизменённые и shell-output.
12. Вывод целиком собирается в чистую копию; hardlink/symlink/FIFO/socket/device и I/O-ошибки отклоняются.
13. Проверка типа использует O_PATH/O_NOFOLLOW до чтения; коллизии имён получают случайный 96-битный суффикс.
    В модельном цикле идентичность пути сохраняется ДО redaction. Компоненты разных исходных путей
    получают разные назначения с учётом уже существующих файлов; повторный исходный путь в этом запуске
    сохраняет назначение для list/read/write. Суффикс берётся из криптографического генератора,
    не выводится из исходного пути и не воспроизводится между запусками распределителя.
    Полный путь очищается до распределения имён, включая секреты с `/`.
    Безопасные канонические компоненты до 255 байт сохраняются без изменений, включая уже
    назначенные суффиксы. Обрезка до 230 байт нужна только при превышении 255 байт или коллизии,
    чтобы добавить точку и случайный 24-значный hex-суффикс в пределах 255 байт.
    После обрезки и выбора суффикса каждый окончательный полный
    префикс проверяется повторно: эти операции могут заново собрать известный секрет через `/`.
    В таком случае текущий компонент целиком заменяется случайным непрозрачным именем;
    результат снова проверяется на секреты и занятость до фиксации назначения и записи на диск.
    Последующая обрезка не применяется. Неудача подбора безопасного уникального имени
    после ограниченного числа попыток отклоняет операцию. Готовые назначения больше не редактируются.
    Общий алгоритм `PathNames` используется моделью и всеми очищающими копиями дерева:
    projection, collection и созданием backup. Каждая запись разрешается по полному исходному
    относительному пути от закреплённого корня назначения: секрет через `/` может сократить
    число компонентов. Общие исходные каталоги сохраняют назначение; разные пути с одинаковым
    очищенным именем получают суффиксы без объединения каталогов и потери содержимого.
    Read также принимает выданный очищенный путь; каноническое имя имеет приоритет
    над привязкой другого исходного пути к имени с суффиксом.
    Повторное разрешение канонического пути идемпотентно, в том числе новым распределителем:
    projection → model read → collection → повторный `copy_tree` сохраняют назначенные имена.
    Неизменённое имя позволяет намеренно редактировать существующий файл; очищенное имя его не перезаписывает.
14. После успешного сбора очищенное дерево возвращается через fd; private metadata хоста сохраняется.
    До первого удаления создаётся полная резервная копия видимого исходного дерева в
    `.env.runner-recovery-<random>` (0700) внутри закреплённого worktree. Имена и содержимое
    очищаются теми же `PathNames`/`redact_bytes`, что и публикуемые артефакты, до записи на диск.
    При ошибке создания этой копии исходное дерево ещё не изменено. При ошибке публикации
    runner очищает частичный результат и восстанавливает очищенное дерево: это допустимое
    публикуемое состояние, а не исходные секретные имена и байты. Повторная очистка при возврате
    не применяется, чтобы сохранить имена, суффиксы коллизий и содержимое самой recovery-копии.
    Publication, rollback и cleanup snapshot копируют уже очищенные полные пути без повторного
    распределения имён; snapshot и восстановленный после ошибки очистки backup сохраняют их точно.
    Если rollback тоже не удался, полная очищенная копия остаётся на диске для ручного
    восстановления; этап всегда завершается failure.
    Recovery-каталог исключён из всех проекций и модельных инструментов как `.env*`.
    Его удаляют только после успешной публикации, восстановления или отказа до изменения исходников.
    Очистка backup выполняется после завершения транзакции: её I/O-ошибка только логируется,
    не превращает успешную публикацию в failure и не подменяет исходную ошибку при rollback.
    До последнего `rmdir` независимая приватная очищенная копия защищает содержимое backup:
    при единичной ошибке его удаления полная recovery-копия восстанавливается и остаётся на диске.
    После успешной публикации или rollback источником истины служит установленное видимое дерево;
    оставшийся backup можно удалить вручную. Двойная ошибка очистки/восстановления не отменяет commit.
15. Нет bwrap, нужной опции, seccomp или namespace не запускается — этап отказывает;
    обхода sandbox и запуска skill напрямую нет. Тесты с bwrap могут быть skipped при его отсутствии,
    но runtime и проверки fail-closed остаются обязательными. Stdout/stderr skill отбрасываются.

Совместимость: проверено с Linux x86_64 и bubblewrap 0.11.1; требуется поддержка `--bind-fd`.
`--unshare-net` намеренно не используется: bwrap настраивает loopback через NETLINK_ROUTE,
что падает на хостах с унаследованным запретом socket, включая среду ревьюеров.
Сеть закрывается обязательным seccomp для всех socket families, без ослабляющего fallback;
IPC/PID namespaces и закрытие fd остаются обязательными. Отдельный регрессионный тест запускает
runner уже под socket-denying seccomp и проверяет успешное выполнение изолированной команды.

Поддерживаемые формы известного секрета: strip/кавычки, base64/base64url с padding и без,
URL-encode с верхним/нижним регистром escapes, hex, Unicode escapes, UTF-8/UTF-16LE/UTF-16BE.
События также маскируют числовые секреты, bearer и credential assignments.

Принятые остаточные риски MVP:

- Redaction не доказывает отсутствие неизвестных секретов, произвольных смешанных/вложенных кодировок,
  шифрования, фрагментов или стеганографии. Skill уже может содержать секрет, переданный самим harness.
- Worktree эксклюзивен для этапа. Враждебный host-процесс того же UID, root и kernel escape вне модели.
- Обновление закреплённого worktree не атомарно для внешнего наблюдателя. При двойной I/O-ошибке
  может остаться частичный результат; очищенное дерево находится в recovery-копии. Оператор должен остановить
  этап и восстановить видимое дерево из этой копии перед продолжением, сохраняя private metadata.
  Recovery не хранит исходные известные секреты; ограничения redaction выше применимы и к ней.
  При двойной ошибке копия хранится до ручного восстановления, после которого оператор удаляет её.
- Восстановление гарантируется для обрабатываемых ошибок процесса; SIGKILL, power loss, повреждение
  файловой системы и физическая потеря носителя не покрыты. Нет crash-durability/fsync-протокола;
  после аварийного завершения оператор проверяет recovery-каталоги вручную.
- Назначения модельных путей живут в пределах одного запуска; после resume новые очищенные имена
  снова учитывают существующие файлы и могут получить новый случайный суффикс.
- Каталог с private metadata, чей полный относительный путь требует очистки/переименования,
  отклоняется до изменения хоста, включая секреты через несколько компонентов.
- Лимиты сбора: 16 MiB/файл, 64 MiB/дерево, 10000 записей, глубина 64. Это не полные CPU/RAM-квоты.
- Системные каталоги должны быть доверенными и не содержать deployment-секретов; сеть и SDK-tools закрыты.
- LOW принят: без отдельного network namespace `/proc/net` раскрывает метаданные сети хоста.
  Seccomp блокирует создание соединений, DNS недоступен; видимость метаданных остаётся.
